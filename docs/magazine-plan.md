# 매거진 확장 계획

역 해부 기사에 역 주변 먹거리·장소와 더 자세한 인터랙션을 더해 "세련된 매거진이자 채널 공식 홈페이지"로 넓힌다. 2026-10-29~30 리서치 기준(heytravel.kr, 미래철도DB, 한우진의 교통평론, 공공데이터, 지도 API). 디자인 요청은 [design-brief.md](./design-brief.md), 검색 규칙은 [seo-geo-strategy.md](./seo-geo-strategy.md).

## 원칙

1. **공식 근거가 있는 것만 싣는다.** 장소는 공식 지정·집계에 이름이 오른 곳(백년가게, 착한가격업소, 모범음식점 등)만 1차 후보로 쓴다. 카드마다 지정 기관·지정 연도·자료 기준일을 숫자 카드와 같은 형식으로 붙인다. 개인 추천은 "에디터 메모" 한 줄로 분리한다.
2. **남의 데이터·사진을 옮기지 않는다.** 네이버 플레이스·카카오맵의 사진·리뷰·메뉴, 다른 매체의 사진·배선도·문장은 쓰지 않는다. 사진은 직접 촬영하거나 업주 서면 허락(크레디트 표기)으로만.
3. **AI로 만든 음식·장소 사진은 쓰지 않는다.** AI 시각화는 3D 단면에만.
4. **지도 SDK를 임베드하지 않는다.** 정적 출구 다이어그램 + 네이버 지도·카카오맵 링크 버튼. 장소 정보는 HTML 텍스트·표로.
5. **협찬은 표시한다.** 제작 지원·협찬이 있으면 기사 상단과 하단에 적는다.

## 경쟁 지형과 차별점

| 상대 | 무엇을 하나 | 우리가 다른 점 |
|---|---|---|
| 한우진의 교통평론(blog.naver.com/ianhan) | 역 구조의 이유, 환승 팁, 배선도. 1~2일에 1편, POWER blog, 네이버 AI 브리핑 누적 인용 39.4만(2026-10 관찰) | 숫자마다 기관·자료명·기준일·URL. 3D 단면. 역 단위 URL과 고정 템플릿(Q&A·숫자 카드). 블로그는 숫자 출처가 약하고 전언 수치가 섞임 |
| 미래철도DB(frdb2.ivyro.net, 같은 운영자) | 계획 중인 노선 DB(스펙표·진행 연표·사업상황 신호등) | 우리는 운행 중인 역. 계획 노선은 `/news/`에서 "바뀌기 전 기록"으로만 |
| heytravel.kr | 인쇄 잡지 기반 여행·라이프 매거진. 감성 서술, 지도·가격 없음, 협찬 미표시, 추적 쿠키 다수 | 공식 근거 장소 카드, 출구·도보 분, 쿠키 없음 |

네이버 검색·AI 브리핑에서는 한우진 블로그가 선점자다. 정면으로 같은 질문을 같은 방식으로 다루면 밀린다. 우리는 "공식 숫자 + 단면 + 역 주변까지 한 페이지"로 차별화하고, 측정은 [geo-test.md](./geo-test.md) 패널에서 경쟁 출처 상위 3에 이 블로그가 나오는지 함께 본다.

## 정보 구조

| 경로 | 섹션 | 내용 | 시점 |
|---|---|---|---|
| `/` | 표지 | 질문 목록, 최신 기사, 노선별 보기, 채널 소개 | 디자인 개편 |
| `/station/<역>/` | #갈아타다 | 역 해부 기사(현행 F안 + 아래 추가 블록) | 디자인 개편 |
| `/station/<역>/around/` | #걷다(먹거리 포함) · #보다 | 역 주변 가이드(출구 다이어그램, 장소 카드, 혼잡 그래프) | 데이터 정리 후 |
| `/line/<노선>/` | 노선 허브 | 노선의 질문 목록, 노선 단위 숫자 | 2단계 |
| `/news/<날짜-슬러그>/` | #바뀌다 | 숫자가 바뀌는 소식(NewsArticle), 계획 노선 진행 | 3단계 |
| `/about/` | 소개 | 운영·정책 | 있음 |

목록 페이지(홈, 노선 허브)는 콘텐츠 데이터에서 생성한다. 같은 정보를 두 곳에 손으로 적지 않는다(미래철도DB는 노선 페이지와 개통시기 페이지가 어긋날 수 있다고 스스로 경고).

## 역 해부 기사에 더할 블록

- **출구·혼잡 블록**(④ 하차 칸 뒤): 출구별 주변 시설(서울교통공사), 시간대별 혼잡 그래프(30분 단위, 평일·주말).
- **하차 칸 바**: 10칸 열차 그림에서 빠른 칸 강조(현행 pin 데이터를 구조화: `{ line, direction, cars: ["10-4"] }`).
- **환승 스텝**: 내림 → 계단·통로 → 갈아탐, 단계별 시간·거리(공사 환승정보 + 직접 측정 표시).
- **비교표**: "구분 | A | B" 열로 개통·연장·승강장 형식 등(필요한 기사만).
- **진행 연표**("무엇이 바뀌나" 근거): `YYYY.M.D 기관 > 문서(고시 제○호)` + URL. 상태 배지는 구상·계획·설계·시공 4단계.
- **역 주변 미리보기**: `/station/<역>/around/`로 가는 장소 카드 3개.
- **관련 기사**: 같은 노선·같은 주제 2개 이상(SEO·GEO 규칙 12).

## 역 주변 가이드 템플릿 (`/station/<역>/around/`)

1. 역명판 + 질문형 제목(예: "사당역 4번 출구, 무엇이 있을까?") + 한 문장 요약
2. 출구 다이어그램(정적 SVG, 번호 핀)
3. 출구별 장소 카드 목록(HTML 목록·표)
4. 시간대별 혼잡 그래프("언제 가면 덜 붐비나")
5. 큐레이션 기준 안내와 출처 전문

장소 카드 필드: 이름 / 공식 근거(지정 기관·연도) / 대표 메뉴·가격(기준일) / 출구 번호·도보 분(직접 측정 표시) / 지도 링크 2개 / 자료 기준일 / 에디터 메모.

## 지도

정적 출구 다이어그램(SVG) + 링크 버튼.
- 네이버 지도 웹: `https://map.naver.com/p/search/<검색어>`
- 카카오맵: `https://map.kakao.com/link/search/<검색어>`, 좌표가 있으면 `https://map.kakao.com/link/map/<이름>,<위도>,<경도>`

지도 SDK(네이버 Dynamic Map 월 600만 건 무료, 카카오 일 30만 건 등)는 "쿠키·외부 스크립트 없음"을 깨고 크롤러가 읽지 못한다. 지표로 필요가 입증될 때만 네이버 Dynamic Map을 검토하고, 그때 CLAUDE.md 개인정보 결정을 고친다.

## 검색·GEO

- 제목은 질문형 유지. 끝에 괄호 키워드를 붙이는 패턴(예: "(승강장, 엘리베이터, 환승 이유)")은 2~3개까지만, SEO·GEO 규칙 4(키워드 반복 금지) 안에서.
- 장소 목록은 `ItemList` + `Restaurant`/`TouristAttraction`을 의미 표시용으로만 넣는다. Google은 Restaurant 캐러셀을 소수 사업자에게만 제공하므로 리치결과는 기대하지 않는다. 별점·리뷰 마크업은 넣지 않는다.
- 지도 대신 HTML 표로 장소명·주소·출구·도보 분을 둔다.

## 하지 말 것

고정폭 레이아웃, 외부 이미지 서버 분산, 추적 쿠키, "~라고 함" 식 전언 숫자, 검색 유입용 생활 키워드 글 섞기, 협찬 미표시, 출처 없는 감성 단정문.

## 일정

1. **지금**: Claude Design 시안 → 디자인 시스템과 홈·역 기사·소개 구현. 역 주변 가이드는 시안만 받고 구현은 데이터 정리 뒤.
2. **디자인 개편 배포일 = 2주 실험 새 D+0**(사용자 결정 2026-10-29). 10-29~개편 전 데이터는 기준선(v1)으로 따로 보고. Umami 이벤트에 `tpl` 속성(v1/v2)을 붙여 구분.
3. **개편 후**: 사당역 1곳으로 역 주변 가이드 시범(공공데이터 다운로드 → 출구별 정리 → 직접 확인 → 카드). 출구·혼잡 블록을 기사 3개에 추가.
4. **2단계**: 노선 허브, 자동 초안 생성기(SEO·GEO 규칙 20 가드레일), 관련 기사 링크.
5. **3단계**: `/news/`(진행 연표·상태 배지), 지도 SDK 재검토(지표 근거가 있을 때만).
