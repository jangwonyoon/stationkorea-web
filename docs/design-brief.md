# Claude Design 브리프 — 매일 그 길 웹 매거진

아래 "프롬프트" 블록을 Claude Design에 그대로 붙여 넣는다. 시안이 확정되면 디자인 토큰·컴포넌트·페이지를 이 레포(Next.js + Tailwind v4)로 옮긴다.

---

## 프롬프트

```
당신은 편집 디자인과 모바일 UX를 함께 맡는 비주얼 디렉터입니다. 한국어 웹 매거진 "매일 그 길"(https://www.stationkorea.com)의 디자인 시스템과 페이지 시안을 모바일 퍼스트로 설계해 주세요. 지금 사이트는 구조만 있고 디자인이 거의 없습니다. 목표는 "세련된 매거진이면서 채널의 공식 홈페이지"입니다. 먼저 아트 디렉션과 UX 원칙을 짧게 제안하고, 그 원칙으로 컴포넌트와 페이지를 만들어 주세요.

# 1. 매체와 독자

- 인스타그램 릴스 채널 @maeil.geugil의 공식 웹사이트입니다. 릴스는 서울 지하철 역·환승통로를 3D 단면으로 뜯어 "왜 이렇게 생겼나"를 60초로 설명합니다.
- 웹 기사 하나는 질문 하나에 답합니다. 예: "사당역, 환승 74m인데 왜 3분 넘게 걸릴까?"
- 차별점은 공식 숫자와 출처입니다. 숫자마다 기준일과 기관 출처(서울교통공사, 서울 열린데이터광장 등)가 붙습니다. 디자인이 이 신뢰를 보여야 합니다. 화려함보다 정확함이 먼저 읽혀야 합니다.
- 앞으로 역 주변 먹거리·추천 장소 큐레이션을 더해 로컬 매거진으로 넓힙니다. 참고: https://heytravel.kr/ 의 세련된 톤과 장소 큐레이션.
- 독자: 서울 지하철 이용자, 도시·지하철 구조에 관심 있는 사람. 대부분 인스타그램 앱 안 브라우저로, 한 손으로 출퇴근길에 읽습니다.

# 2. 핵심 사용자 흐름과 디자인 목표

흐름: 릴스 → 인스타 프로필 링크 → 홈 또는 기사 → 첫 화면에서 답을 얻음 → 끝까지 읽음 → 다음 질문으로 이동.
측정 지표(디자인이 올려야 할 숫자): 다음 질문 클릭률 25% 이상, 본문 끝(출처 목록) 도달률 40% 이상.

- 첫 화면(390×~660px, 인스타 인앱 브라우저 상하단 바 제외)에서 질문과 한 문장 답이 스크롤 없이 보여야 합니다. 3D 단면 이미지는 그 아래에서 시작해도 됩니다.
- 숫자 3개는 스크롤 한 번 안에서 한눈에 비교되게.
- 끝까지 읽게 만드는 리듬: 긴 텍스트 사이에 숫자·이미지·하차 칸 안내가 쉼표 역할.
- 다음 질문 카드는 "다음 기사"가 아니라 "다음 궁금증"으로 느껴지게. 본문 끝과 출처 사이에 자연스럽게.
- 홈에서는 역 이름이 아니라 질문이 주인공. 처음 온 사람이 3초 안에 "무슨 매체인지"와 "무엇부터 읽을지"를 알아야 합니다.

# 3. 모바일 퍼스트 규칙

- 기준 폭 390px(최소 360px 확인), 그다음 768px·1280px로 확장. 데스크톱은 모바일을 늘린 것이 아니라 본문 왼쪽, 숫자 카드·릴스·다음 질문을 오른쪽에 고정한 2열.
- 인스타 인앱 브라우저: 상단 바와 하단 바가 화면을 가립니다. 화면 하단에 고정 요소를 두지 않거나 safe-area를 지킵니다. hover에 기대는 정보는 없게.
- 터치 영역 최소 44×44px, 엄지 영역(화면 하단 1/3)에 주요 다음 행동(다음 질문, 릴스 보기).
- 한글 타이포: 본문 16~17px, 행간 1.7 안팎, 한 줄 30~38자, word-break: keep-all. 제목은 줄바꿈 위치를 고려(긴 질문 47자까지 2~3줄).
- 숫자는 tabular, 단위(m, 분, 초, 명, %)와 숫자의 크기 관계를 설계.
- 헤더는 얇게. 스크롤하면 숨겨지거나 최소화. 햄버거 메뉴보다 노출된 내비게이션 2~3개(질문, 노선, 소개)를 우선 검토.
- 출처 전문은 길어도 접지 않고 보입니다(검색·AI 인용 때문). 대신 작은 글자·여백으로 위계를 낮춥니다.

# 4. 아트 디렉션

- 주제: 서울 지하철 안내 체계(역명판, 노선 원형 번호, 출구 번호, 승강장 칸 번호 "10-4")를 매거진 언어로 옮깁니다. 가장 눈에 띄는 장치는 하나만: 기사 첫 화면의 역명판(노선색 띠 + "방배 ← 사당 → 낙성대"). 나머지는 조용하게.
- 노선은 글자 대신 공식 노선색 원형 번호로(색만으로 구분하지 않고 번호 포함). 공식 노선색: 1호선 #0052A4, 2호선 #00A84D, 3호선 #EF7C1C, 4호선 #00A5DE, 5호선 #996CAC, 6호선 #CD7C2F, 7호선 #747F00, 8호선 #E6186C, 9호선 #BDB092. 기사의 강조색은 그 역 노선색. 환승역(2개 노선)은 두 색을 어떻게 다룰지 규칙을 제안.
- 3D 단면 렌더(콘크리트 회색 톤, 초록·하늘색 열차, 숫자 태그)가 주인공입니다. 4:5 세로 비율 기본, 자르기 규칙과 캡션 위치 제안. 이미지 위에 글자를 얹지 않습니다(이미지 안에 이미 숫자 태그가 있음).
- 바탕은 렌더와 어울리는 차가운 콘크리트 계열, 글자는 먹색. 색은 노선색 외에 거의 쓰지 않습니다.
- 서체: 한글 세리프 제목 + 기술적인 산세리프 본문·숫자. Google Fonts에서 쓸 수 있는 것(예: 제목 Hahmlet, 본문 IBM Plex Sans KR). 더 나은 조합이 있으면 이유와 함께 제안.
- 피할 것: 크림색 바탕 + 테라코타, 대문자 라벨, "A · B · C" 식 메타 나열, 똑같은 둥근 카드와 그림자 반복, 그라데이션 장식, 이모지, 모든 섹션에 등장 애니메이션.
- 움직임: 한 곳에만. 예를 들어 기사 진입 시 역명판의 노선 띠가 한 번 그려지는 정도. prefers-reduced-motion 존중.
- heytravel.kr에서 가져올 것: 넉넉한 사진 그리드, 장소마다 "소제목 + 짧은 서술 + 고정 정보 줄" 반복 블록, 인쇄 잡지식 번호 핀 일러스트 지도, 기사 끝 추천 블록. 가져오지 않을 것: 출처 없는 감성 문장, 협찬 미표시.
- 섹션 이름은 짧은 동사형 해시태그로: #갈아타다(역 해부) · #먹다 · #보다.

# 5. 만들 것

A. 디자인 토큰: 색(라이트 기준, 다크 모드 제안은 선택), 타입 스케일(모바일·데스크톱), 간격, 그리드(모바일 4열·데스크톱 12열 등), 모서리·선 규칙, 노선색 체계.

B. 컴포넌트(상태 포함: 기본, 눌림, 키보드 포커스, 긴 텍스트):
- 노선 원형 번호(1~9호선, 크기 3단계)
- 역명판(단일 노선, 환승역)
- 숫자·출처 카드(큰 숫자 + 설명 + 기준일 + 각주 번호), 표로 마크업 가능한 구조
- 하차 칸 안내(승강장 칸 표기 "10-4"처럼, 방면별)
- 릴스 링크(9:16 썸네일, "인스타그램에서 보기")
- Q&A 블록(질문 소제목 + 답 단락 + 출처 각주)
- 다음 질문 카드
- 출처 목록, 바이라인(글 윤장원 + 게시일·갱신일), 정정 기록
- 헤더·푸터(소개·문의 링크)
- 장소 카드(먹거리·명소): 이름, 공식 근거 배지(예: "중기부 백년가게", "행안부 착한가격업소", 지정 연도·자료 기준일), 대표 메뉴·가격(기준일), 출구 번호·도보 분, 에디터 메모 한 줄(공식 정보와 시각적으로 분리), 지도 링크 버튼 2개(네이버 지도·카카오맵). 공공데이터에는 사진이 없으므로 사진이 없는 카드가 기본, 사진이 있는 경우(업주 제공, 크레디트 표기)는 변형.
- 출구 다이어그램: 역을 중심으로 출구 번호와 주변 장소 핀을 그린 정적 일러스트 지도(인쇄 잡지식 번호 핀). 지도 앱을 임베드하지 않습니다.
- 시간대별 혼잡 그래프: 30분 단위 막대(서울교통공사 혼잡도 %), 평일·주말 전환, 출처·기준일 표기. SVG로 그릴 수 있는 단순한 형태.
- 하차 칸 바: 10칸 열차 그림에서 빠른 칸을 강조(방면별).
- 환승 스텝 카드: 내림 → 계단·통로 → 갈아탐을 단계별로(소요 시간, 거리).

C. 페이지 시안, 각각 390px과 1280px:
1. 홈 = 매거진 표지. 최신 기사 1개 크게 + 질문 목록 + 노선별 보기(원형 번호) + 채널 소개.
2. 역 기사(사당역). 모바일 순서: ① 역명판 + 질문 제목(H1) + 한 문장 답 + 바이라인 ② 3D 단면 이미지 ③ 숫자 카드 3개 ④ 하차 칸 ⑤ 릴스 ⑥ Q&A 4개 ⑦ 다음 질문 "그럼 건대입구는 왜?" ⑧ 출처 전문·정정 기록·제작 문의.
3. 역 주변 가이드(새 페이지, 사당역, #먹다·#보다): 출구 다이어그램 → 출구별 장소 카드 → 시간대별 혼잡 그래프("언제 가면 덜 붐비나") → 큐레이션 기준 안내("공식 지정·집계에 이름이 오른 곳만 싣습니다"). 가게 이름은 지어내지 말고 "[가게 이름]", "[메뉴]"처럼 예시로 표시. AI로 만든 음식 사진은 쓰지 않습니다.
4. 노선 허브(2호선): 노선의 질문 목록과 노선 단위 숫자.
5. 소개: 만드는 사람, 제작 방식, 출처·정정 정책, AI 사용 범위, 방문 통계 안내, 연락처.

D. 기사 첫 화면을 360px·390px에서 인스타 인앱 브라우저 바를 그린 상태로 한 번 더 보여 주세요(질문과 답이 첫 화면에 들어오는지 확인용).

# 6. 실제 콘텐츠 (사당역 기사)

- 질문: 사당역, 환승 74m인데 왜 3분 넘게 걸릴까?
- 한 문장 답: 사당역 2호선과 4호선의 최단 환승거리는 74m(서울교통공사, 2026-08-31 기준)지만, 좁은 계단에 출퇴근 환승객이 엉키지 않도록 방배 방면 통로에 펜스를 쳐 돌아가게 하고 간이 통로는 출근 시간에 셔터를 내리기 때문에, 공사 안내 기준 환승 시간은 방배 방면 3분 22초입니다.
- 노선: 2호선, 4호선. 역명판(2호선): 방배 ← 사당 → 낙성대
- 숫자 카드: 74m(2호선↔4호선 최단 환승거리, 2026-08-31 기준) / 3분 22초(공사 안내 환승 시간, 방배 방면↔4호선, 2026-09-01 기준) / 160,478명(평일 환승 인원, 73개 환승역 중 6위, 2026-06-30 기준)
- 하차 칸: 4호선 총신대입구 방면 10-4, 남태령 방면 1-1에서 내리면 2호선 방배 방면이 가장 빠름. 낙성대 방면은 4-2, 7-3.
- Q&A 제목: 사당역은 왜 눈앞의 계단을 막아 놓고 돌아가게 하나요? / 어디서 내리면 빠른가요? / 얼마나 붐비나요? / 앞으로 무엇이 바뀌나요?
- 다른 기사: 잠실역, 2호선에서 8호선까지 왜 이렇게 멀까?(2·8호선) / 건대입구역, 걸으면 77m인데 휠체어는 왜 1,400m일까?(2·7호선)
- 바이라인: 글 윤장원, 2026년 10월 29일 게시

# 7. 기술 제약

- 정적 사이트(Next.js 정적 내보내기 + Tailwind CSS v4). 큰 라이브러리 없이 CSS로 구현 가능한 수준.
- 제목(H1)·한 문장 답·숫자 표·하차 칸·출처 목록은 이미지가 아니라 실제 텍스트(검색·AI 인용).
- 접근성: 본문 대비 WCAG AA, 키보드 포커스 표시, 색만으로 정보 전달하지 않기, 이미지 대체 텍스트 자리.
- 성능: 첫 화면 이미지 1장만 우선 로드, 웹폰트는 2종 이내.
- 쿠키·외부 추적 스크립트 없음. 지도 SDK를 임베드하지 않습니다. 지도는 정적 출구 다이어그램 + 네이버 지도·카카오맵 링크 버튼(인앱 브라우저에서 누르면 지도 앱으로 넘어감). 장소명·주소·출구·도보 분은 HTML 텍스트로.

# 8. 결과물과 평가 기준

결과물: 아트 디렉션·UX 원칙 요약 1장, 디자인 토큰 표, 컴포넌트 시트(상태 포함), 페이지 시안(390·1280), 첫 화면 확인 시안. 가능하면 HTML/CSS로 내보낼 수 있는 형태.

스스로 아래로 점검해 주세요.
- 390px 첫 화면에 질문과 한 문장 답이 들어오는가
- 처음 보는 사람이 3초 안에 매체의 정체를 아는가
- 숫자와 출처가 신뢰감 있게 읽히는가, 장식처럼 보이지 않는가
- 다음 질문 카드가 엄지로 누르기 쉬운 위치·크기인가
- 노선색 하나를 빼도 정보가 전달되는가
```
