# Claude Design 브리프 — 매일 그 길 웹 매거진

아래 "프롬프트" 블록을 Claude Design에 그대로 붙여 넣는다. 시안이 확정되면 디자인 토큰·컴포넌트·페이지를 이 레포(Next.js + Tailwind v4)로 옮긴다.

---

## 프롬프트

```
서울 지하철 역을 다루는 한국어 웹 매거진 "매일 그 길"(https://www.stationkorea.com)의 비주얼 디자인 시스템과 주요 페이지 시안을 만들어 주세요. 지금 사이트는 구조만 있고 디자인이 거의 없는 상태입니다. 세련된 매거진, 그리고 채널의 공식 홈페이지처럼 보여야 합니다.

## 무엇을 하는 매체인가
- 인스타그램 릴스 채널 @maeil.geugil의 공식 웹사이트입니다. 릴스는 지하철 역·환승통로를 3D 단면으로 뜯어 "왜 이렇게 생겼나"를 60초로 설명합니다.
- 웹 기사 하나는 질문 하나에 답합니다. 예: "사당역, 환승 74m인데 왜 3분 넘게 걸릴까?"
- 차별점은 공식 숫자와 출처입니다. 모든 숫자에 기준일과 기관 출처가 붙습니다(서울교통공사, 서울 열린데이터광장 등). 이 신뢰감이 디자인에서도 느껴져야 합니다.
- 앞으로 역 주변 먹거리·추천 장소 큐레이션을 더해 여행·로컬 매거진처럼 넓힙니다. 참고: https://heytravel.kr/ 의 세련된 매거진 톤과 장소 큐레이션 방식.

## 독자와 환경
- 한국어, 모바일 우선. 대부분 인스타그램 앱 안 브라우저로 들어옵니다(폭 390px 기준). 데스크톱(1280px)도 함께.
- 서울 지하철 이용자, 도시·지하철 구조에 관심 있는 사람.

## 디자인 방향 (제안, 더 나은 안이 있으면 바꿔도 됩니다)
- 서울 지하철 안내 체계(역명판, 노선 원형 번호, 출구 번호, 승강장 칸 번호 표기)를 매거진 언어로 옮깁니다. 가장 눈에 띄는 장치는 하나만: 기사 첫 화면의 역명판(노선 색 띠 + "이전 역 ← 역 이름 → 다음 역").
- 노선은 글자 대신 공식 노선색 원형 번호로 표시합니다. 서울 지하철 공식 노선색: 1호선 #0052A4, 2호선 #00A84D, 3호선 #EF7C1C, 4호선 #00A5DE, 5호선 #996CAC, 6호선 #CD7C2F, 7호선 #747F00, 8호선 #E6186C, 9호선 #BDB092. 각 기사의 강조색은 그 역 노선색을 따릅니다.
- 바탕은 3D 단면 렌더와 어울리는 차가운 콘크리트 회백색 계열, 글자는 먹색. 사진(3D 단면 렌더)이 주인공이 되게 여백을 넉넉히.
- 서체: 한글 세리프 제목(예: Hahmlet) + 기술적인 산세리프 본문·숫자(예: IBM Plex Sans KR) 같은 조합. Google Fonts에서 쓸 수 있는 서체로. 숫자는 tabular.
- 피할 것: 크림색 배경 + 테라코타 강조, 대문자 라벨, "A · B · C" 식 메타 나열, 똑같은 둥근 카드에 그림자 반복, 그라데이션 장식, 이모지.

## 만들 것
1. 디자인 토큰: 색(라이트 기준, 다크는 선택), 서체·타입 스케일, 간격, 노선색 체계.
2. 컴포넌트: 노선 원형 번호(1~9호선), 역명판(기사 상단), 숫자·출처 카드(큰 숫자 + 설명 + 기준일 + 각주 번호), 하차 칸 안내(예: "10-3" 칸 번호를 승강장 표기처럼), 릴스 썸네일 링크(9:16, "인스타그램에서 보기"), Q&A 블록, "다음 질문" 카드, 출처 목록, 바이라인(글 윤장원 + 날짜), 정정 기록, 헤더·푸터, 장소 카드(먹거리·명소: 사진, 이름, 한 줄 소개, 역 출구·도보 분, 출처나 근거, 지도 링크).
3. 페이지 시안 (각각 390px, 1280px):
   a. 홈 = 매거진 표지. 역 이름이 아니라 질문 목록이 주인공. 최신 기사 크게 1개 + 질문 목록 + 노선별 보기 + 인스타 채널 안내.
   b. 역 기사(사당역 내용으로). 모바일 순서: ① 역명판 + 질문 제목(H1) + 한 문장 답 ② 3D 단면 이미지(4:5) ③ 숫자·출처 카드 3개 ④ 하차 칸 안내 ⑤ 릴스 썸네일 ⑥ Q&A 4개 ⑦ "그럼 건대입구는 왜?" 다음 질문 ⑧ 출처 전문·정정 기록·제작 문의. 데스크톱은 본문 왼쪽, 숫자 카드·릴스·다음 질문을 오른쪽에 고정.
   c. 역 주변 가이드(새 페이지, 사당역 예시): 역 출구별로 먹거리·장소 카드, 지도 영역(정적 지도 이미지 + "네이버 지도에서 보기" 링크 자리), 큐레이션 기준(공식 데이터 근거) 안내. 장소 데이터는 실제 가게 이름을 지어내지 말고 "[가게 이름]", "[메뉴]"처럼 예시임이 보이게.
   d. 노선 허브(2호선 예시): 이 노선의 질문 목록과 노선 단위 숫자.
   e. 소개(About): 만드는 사람, 제작 방식, 출처·정정 정책, AI 사용 범위, 방문 통계 안내, 연락처.

## 실제 콘텐츠 (사당역 기사)
- 질문: 사당역, 환승 74m인데 왜 3분 넘게 걸릴까?
- 한 문장 답: 사당역 2호선과 4호선의 최단 환승거리는 74m(서울교통공사, 2026-08-31 기준)지만, 좁은 계단에 출퇴근 환승객이 엉키지 않도록 방배 방면 통로에 펜스를 쳐 돌아가게 하고 간이 통로는 출근 시간에 셔터를 내리기 때문에, 공사 안내 기준 환승 시간은 방배 방면 3분 22초입니다.
- 노선: 2호선, 4호선. 역명판 예: 방배 ← 사당 → 낙성대 (2호선)
- 숫자 카드: 74m(2호선↔4호선 최단 환승거리, 2026-08-31 기준) / 3분 22초(공사 안내 환승 시간, 방배 방면↔4호선, 2026-09-01 기준) / 160,478명(평일 환승 인원, 73개 환승역 중 6위, 2026-06-30 기준)
- 하차 칸: 4호선 총신대입구 방면 10-4, 남태령 방면 1-1에서 내리면 2호선 방배 방면이 가장 빠름. 낙성대 방면은 4-2, 7-3.
- Q&A 제목: 왜 눈앞의 계단을 막아 놓고 돌아가게 하나요? / 어디서 내리면 빠른가요? / 얼마나 붐비나요? / 앞으로 무엇이 바뀌나요?
- 다른 기사: 잠실역, 2호선에서 8호선까지 왜 이렇게 멀까?(2·8호선) / 건대입구역, 걸으면 77m인데 휠체어는 왜 1,400m일까?(2·7호선)
- 이미지: 콘크리트 톤 3D 단면 렌더(초록 2호선 열차, 하늘색 4호선 열차, 계단에 74m·3:22 표시)

## 지켜야 할 제약
- 검색·AI 인용이 최우선입니다. 제목(H1)·한 문장 답·숫자 표·출처 목록은 이미지가 아니라 실제 텍스트여야 하고, 숫자 카드는 표로 마크업할 수 있는 구조여야 합니다.
- 정적 사이트(Next.js 정적 내보내기 + Tailwind CSS v4). 무거운 애니메이션·라이브러리 없이. 움직임은 한 곳에만 절제해서.
- 접근성: 본문 대비 WCAG AA, 키보드 포커스 표시, 노선색만으로 정보를 전달하지 않기(번호 함께).
- 쿠키·외부 추적 스크립트 없음. 지도는 지금은 정적 이미지 + 외부 지도 링크 자리로.
```

## 시안 확정 뒤 구현 순서 (이 레포)

1. 토큰을 `src/app/globals.css`(@theme)로, 서체는 `next/font/google`로 빌드 시 포함(외부 요청 없음).

4. 배포일을 2주 실험의 새 D+0으로 `docs/geo-log.md`에 기록(개편 전 데이터는 기준선).
